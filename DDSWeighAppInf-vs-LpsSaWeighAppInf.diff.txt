DDSWeighAppInf.hpp vs LpsSaWeighAppInf.hpp -- full diff + removal notes
======================================================================
Old file (untouched original, byte-identical to reference tree):
  cpm/CPM-Loader-ais/prod/common/interfaces/LpsSaWeighReqstChannel/LpsSaWeighAppInf.hpp
New file (separate class, does NOT replace the old file):
  cpm/CPM-Loader-ais/prod/common/interfaces/LpsSaWeighReqstChannel/DDSWeighAppInf.hpp

IMPORTANT: this is not an in-place edit. LpsSaWeighAppInf.hpp still exists,
unchanged, in the repo -- AisJhm2RequestProcessor.cpp (legacy UI infra,
prod/infrastructure/aisJhm/aisJhm2/) holds its own instance of it and calls
the very methods this new class drops. DDSWeighAppInf.hpp is a new,
additional file that only LpsSaJobMgrApp's weighAppInf_ member uses instead.
See LpsSaJobMgrApp.h for the include/member swap.

======================================================================
PART 1 -- Public methods removed (present in old, absent in new) and why
======================================================================

1. bool start(appName, requestOutputName, responseInputName, txInputName)
   (the 4-string-name overload that calls task::InterfaceDb::bind()
   internally)
   Why not needed: task::InterfaceDb::bind() is the AIS SCS task-framework's
   channel-name-to-pointer lookup. There is no ROS2 equivalent, and nothing
   in LpsSaJobMgrApp.cpp calls this overload -- the app already constructs
   its ros2_wrapper::RosOutputInterface/RosInputInterface objects directly
   in initialize() and passes the pointers straight to the remaining
   4-pointer start() overload. Kept out rather than reimplemented because
   there was no real caller to preserve (checked LpsSaJobMgrApp.cpp,
   LpsSaJobMgrScs.cpp, LpsSaJobMgrProcess.cpp).

2. bool waitForResponse(timeoutDuration)
   Why not needed: blocking wait on responseDataCv_ for a response to
   arrive, independent of tx data. No call site in LpsSaJobMgrScs.cpp uses
   this directly -- JobMgr only ever waits for tx data (waitForTxData()),
   which itself already factors in whether a response has been seen (via
   nextTxTimePoint_/nextTxTimePointNs_). Only real caller found anywhere in
   the codebase is AisJhm2RequestProcessor, indirectly through
   sendRequestGetResponse() (see #4) -- not JobMgr.

3. bool sendRequestWaitForTxData(request, txData, timeoutDuration)
   Why not needed: a convenience wrapper that just calls sendRequest() then
   waitForTxData(). LpsSaJobMgrScs.cpp always calls sendRequest() and
   waitForTxData() as two separate explicit steps (with other logic
   in between, e.g. logging/state updates) -- this combined-call overload
   has no caller in JobMgr.

4. bool sendRequestGetResponse(request, response, timeoutDuration)
   Why not needed: sends a request, then blocks via waitForResponse() for
   the matching response and returns it. This is the method that surfaced
   the whole issue -- AisJhm2RequestProcessor::processFileRequestServiceHistory()
   calls exactly this (weighAppInf_.sendRequestGetResponse(request, response)),
   but that call site belongs to AisJhm2RequestProcessor's own separate
   LpsSaWeighAppInf instance, not to LpsSaJobMgrApp's. JobMgr itself never
   calls this method (confirmed via grep of LpsSaJobMgrScs.cpp/.cpp/.h) --
   it only ever needs the response to update its own internal freshness
   gate, which drainResponseInput() (renamed from notifyResponseInput())
   still does internally, just without exposing the response object or
   blocking for it.

5. void getLastResponse(response)
   Why not needed: returns a copy of the last received LpsSaWeighRespChannel
   response, used only by sendRequestGetResponse() (#4) to hand the response
   back to its caller. Since #4 isn't needed by JobMgr, this accessor isn't
   either -- JobMgr never reads response fields itself, only whether/when a
   response arrived (used internally to gate tx-data freshness).

======================================================================
PART 2 -- Internal machinery removed (protected/private) and why
======================================================================

6. std::mutex mtx_
   Why not needed: guarded all shared state against concurrent access
   between the boost::signals2 callback thread (notifyResponseInput()/
   notifyTxInput(), invoked asynchronously whenever new SCS data arrived)
   and the app's own executive()-thread callers of sendRequest()/
   waitForTxData(). The ROS2 wrapper (RosInputInterface<T>) has no
   callback/notification thread at all -- data is only ever pulled via
   get(), and that pull only ever happens from inside drainResponseInput()/
   drainTxInput(), which only ever run synchronously inside waitForTxData(),
   which itself only ever runs on the same executive()-tick thread as
   spin_some(). Single thread touches this state -> no lock needed.

7. std::condition_variable txDataCv_
   Why not needed: used by the old blocking waitForTxData() to sleep until
   notifyTxInput()/notifyResponseInput() (running on the callback thread)
   signaled new data, or until timeoutDuration elapsed. There is no
   callback thread left to signal it (see #6), and no way to "wake early"
   under a poll-only model -- waitForTxData() in the new class is a
   single-shot, non-blocking poll of whatever spin_some() already delivered
   this tick, so there's nothing to wait on.

8. std::condition_variable responseDataCv_
   Why not needed: same reasoning as #7, but backed waitForResponse() (#2)
   instead. Removed together with #2 since it has no other use.

9. LpsSaWeighRespChannel responseData_ (member storing "last received
   response")
   Why not needed: only ever read by getLastResponse() (#5), which itself
   is only used by sendRequestGetResponse() (#4). With both of those gone,
   nothing reads this member, so it's gone too. Note drainResponseInput()
   (the renamed notifyResponseInput()) still processes each incoming
   response to update the freshness gate (nextTxTimePointNs_) -- it just no
   longer stashes a copy for later retrieval.

10. boost::signals2::connection responseInputConnection_
11. boost::signals2::connection txInputConnection_
    Why not needed: these tracked subscriptions created via
    responseInput_->addNewDataSlot(...)/txInput_->addNewDataSlot(...) in the
    old start(), so stop() could later call removeNewDataSlot(...) to
    unsubscribe. RosInputInterface<T> has no addNewDataSlot()/callback
    registration at all -- it's polled directly via get(), so there is
    nothing to "connect" or "disconnect" in the first place. This is also
    why the new stop() is just `return true;` with no teardown logic.

12. #include <mutex>, <condition_variable>, <boost/signals2.hpp>
    Why not needed: direct consequence of removing #6-#11 above -- nothing
    in the new file uses any mutex, condition_variable, or boost::signals2
    type anymore.

PART 4 -- Kept as-is (unchanged role)

                                waitForTxData() in the new class now
                                ignores its passed-in value; see the
                                (void)timeoutDuration comment in the code
                                and the class-level comment explaining why
                                no real blocking wait is possible under a
                                poll-only interface)

                                   types instead of SCS Output/Input types
  stop()                     -- kept (now a no-op returning true, see #10/#11)
  sendRequest()               -- kept, retyped to the .msg request type
  waitForTxData()             -- kept, retyped, now polls instead of blocks
  appName_, lastRequestId_, lastCommand_, txData_ -- all kept, same purpose
