JobMgr SCS->ROS2 Channel Migration -- Jira User Story Template
=============================================================================
Covers the 13 remaining JobMgr channels (16 total, 3 done -- see
Full_ROS2_Migration_Analysis.txt and MsgFile-Completion-Status.txt).
.msg conversion is already complete for all channels; this covers the
remaining C++-side work only (type, binding, call sites).

CURRENT APPROACH: ONE user story for the whole effort, with generic,
reusable tasks (parameterized by complexity tier, not by channel name)
scheduled across the 4-week sprint. A per-channel story template is also
kept further below for reference, but is NOT the approach in use.


=============================================================================
USER STORY (one, covers the whole effort)
=============================================================================

Title:
Migrate JobMgr's remaining SCS channels to ROS2/DDS transport

Description:
JobMgr has 16 total channels; 3 (LpsSaWeighReqstChannel/RespChannel/
TxChannel) are already migrated to ros2_wrapper. This story covers
converting the remaining 13 channels from SCS InterfaceDb-bound objects
to ROS2/DDS wrappers, using the same conversion pattern already proven
on the 3 completed channels. .msg generation is already done for all 16
-- this story covers only the C++ side (type, binding, call sites).

Definition of Ready (DoR):
- .msg file for each channel already generated (confirmed in
  MsgFile-Completion-Status.txt)
- Topic names agreed for all 13 remaining channels
- Any hardware/PID constants a channel depends on are confirmed, not
  placeholders (affects OutputChannel, DataLinkData specifically)
- Complexity tier assigned per channel (XL/L/M/S) so day allocation is
  known before work starts

Acceptance Criteria (short):
- All 13 channels' members retyped from raw SCS pointer to
  ros2_wrapper::Ros{Output,Input}Interface<msg::T>*
- Zero remaining InterfaceDb::bind() calls anywhere in JobMgr
- All read/write call sites use generated .msg snake_case fields, not
  old SCS getters/field names
- Code builds clean with zero references to any old SCS channel type
- All 16 channels (13 new + 3 already done) verified live together in
  one integration pass, not just individually
- No regression in the 3 already-completed channels

Definition of Done (DoD):
- All 13 channels merged, reviewed, building clean
- Full 16-channel integration pass completed and signed off
- Challenges-And-Decisions.txt updated with anything non-obvious found
  during conversion
- Story closed only after Week 4's integration task passes, not
  per-channel

Worked example (fully filled in -- LpsSaJobMgrReqstChannel):

Title:
Migrate LpsSaJobMgrReqstChannel from SCS to ROS2/DDS (JobMgr)

Description:
As the JobMgr app, LpsSaJobMgrReqstChannel currently reads incoming
UI/WeighApp requests through the old SCS InterfaceDb-bound
LpsSaJobMgrScsReqstIn object. Convert it to
ros2_wrapper::RosInputInterface<cpm_common_interfaces::msg::LpsSaJobMgrReqstChannel>
so it no longer depends on InterfaceDb.

Definition of Ready (DoR):
- LpsSaJobMgrReqstChannel.msg (cpm_common_interfaces) already generated
- Topic name agreed: lps_sa_job_mgr_reqst_channel
- No hardware constants involved -- not blocked

Acceptance Criteria:
- LpsSaJobMgrScsReqstIn retyped to
  ros2_wrapper::RosInputInterface<cpm_common_interfaces::msg::LpsSaJobMgrReqstChannel>*
- InterfaceDb::bind("LpsSaJobMgrReqstChannelInput", ...) removed,
  replaced with constructor call bound to lps_sa_job_mgr_reqst_channel
- Every reqIn.<field> access in LpsSaJobMgrScsChkForReqst() (both the
  top-level command switch and the "new-style requests" sub-loop) uses
  .msg snake_case fields, e.g. reqIn.command.value, reqIn.data_target_type
- sendReqstResponse() correctly reads from the converted reqIn type
- Code builds with zero references to old LpsSaJobMgrReqstChannelInput type
- Manually triggering each of the ~25 request commands produces the
  expected LpsJobMgrJobTrackerInfoTbl/task state change

Definition of Done (DoD):
Merged, reviewed, builds, manually verified per-command, verified
jointly with LpsSaJobMgrRespChannel (response mirrors request),
Challenges-And-Decisions.txt updated with any surprises.

Tasks:
1. Update LpsSaJobMgrApp.h: retype LpsSaJobMgrScsReqstIn
2. Update initialize(): replace bind with RosInputInterface construction
   on lps_sa_job_mgr_reqst_channel
3. Convert LpsSaJobMgrScsChkForReqst() field accesses (command switch +
   new-style requests loop)
4. Convert sendReqstResponse() to match
5. Remove unused SCS include if safe
6. Build + smoke-test all ~25 commands individually
7. Joint verification with LpsSaJobMgrRespChannel
