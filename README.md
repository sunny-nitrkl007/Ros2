# ROS2 Discovery Server — YAML Driven Code Generator

A YAML-driven code generation framework for ROS2 nodes.
Define your system in YAML, run the generator, get production-ready C++ ROS2 nodes.
Currently implements a single publisher / subscriber pair tested with a Fast-DDS Discovery Server.

---

## Folder Structure

```
discoveryTesting/
├── tool/                                    # Reusable infrastructure — never changes between projects
│   ├── generator.py                         # Code generator (reads YAML + Jinja, writes C++)
│   ├── Dockerfile                           # Builds a ROS2 Jazzy container with the package pre-built
│   ├── entrypoint.sh                        # Container entrypoint — sources ROS2 automatically
│   ├── client.xml                           # Fast-DDS SUPER_CLIENT profile (nodes use discovery server)
│   └── server.xml                           # Fast-DDS SERVER profile (optional, for custom server config)
│
└── discovery_server_single_pub_sub/         # Project — only this changes per system
    ├── config/                              # All YAML inputs
    │   ├── nodes/
    │   │   ├── talker.yaml                  # Publisher node definition
    │   │   └── listener.yaml               # Subscriber node definition
    │   ├── application.yaml                 # System name, ROS domain ID, node list
    │   ├── topics.yaml                      # Topic name to message type mapping
    │   ├── qos_profiles.yaml               # Named QoS profiles (reliable, best_effort, etc.)
    │   ├── parameters.yaml                  # Node runtime parameters
    │   └── discovery.yaml                   # Discovery server address and port reference
    ├── templates/                           # Jinja2 C++ templates
    │   ├── publisher.cpp.jinja
    │   ├── subscriber.cpp.jinja
    │   ├── node.hpp.jinja
    │   ├── CMakeLists.txt.jinja
    │   └── package.xml.jinja
    └── generated_pkg/                       # Output — generated by running generator.py
        ├── include/
        ├── src/
        ├── CMakeLists.txt
        └── package.xml
```

## Step 1 — Understand the YAML Config

### `config/application.yaml`
Defines the system name, ROS domain ID, and which nodes to generate.
```yaml
application:
  name: demo_system
  domain_id: 10
  nodes:
    - talker
    - listener
```

### `config/nodes/talker.yaml`
Each node file defines the node fully — type, topic, QoS profile, parameters.
```yaml
node:
  name: talker
  type: publisher
  topic: chatter
  qos: default_qos
  parameters: talker
  executor: multi_threaded
```

### `config/topics.yaml`
Maps topic names to ROS2 message types.
```yaml
topics:
  chatter:
    type: std_msgs/msg/String
```

### `config/qos_profiles.yaml`
Named QoS profiles reused across nodes.
```yaml
qos_profiles:
  default_qos:
    reliability: reliable
    durability: volatile
    history: keep_last
    depth: 10
  best_effort_qos:
    reliability: best_effort
    history: keep_last
    depth: 10
```

### `config/parameters.yaml`
Runtime parameter values per node.
```yaml
parameters:
  talker:
    publish_rate: 2.0
  listener:
    log_prefix: "Received:"
```

## Step 2 — Run the Generator

From the `discoveryTesting/` root:

```bash
python tool/generator.py --project discovery_server_single_pub_sub
```

The `--project` flag tells the generator which project folder to use.
Output is written to `discovery_server_single_pub_sub/generated_pkg/`.

Expected output:
```
===== CONFIG LOAD SUMMARY =====
Project           : discovery_server_single_pub_sub
Application name  : demo_system
Domain ID         : 10
Nodes             : ['talker', 'listener']
...
===== GENERATION COMPLETE =====
```

Generated files:
- `generated_pkg/src/talker.cpp`
- `generated_pkg/src/listener.cpp`
- `generated_pkg/include/talker.hpp`
- `generated_pkg/include/listener.hpp`
- `generated_pkg/CMakeLists.txt`
- `generated_pkg/package.xml`

## Step 3 — Build the Docker Image

From `discoveryTesting/` (**always run from here, not from inside `tool/`**):

```bash
cd discoveryTesting/
docker build --no-cache -f tool/Dockerfile -t ros2_discovery_test .
```

> **Important:** Two flags are required:
> - `-f tool/Dockerfile` — Dockerfile lives inside `tool/`
> - `.` — build context must be `discoveryTesting/` so Docker can reach both
>   `discovery_server_single_pub_sub/generated_pkg/` and `tool/entrypoint.sh`
>
> Running `docker build` from inside `tool/` will fail with `not found` errors
> because Docker cannot see the project folder from there.

This step:
1. Pulls `ros:jazzy` base image
2. Copies `generated_pkg/` into the container
3. Runs `colcon build` to compile the C++ nodes
4. Sets `AMENT_PREFIX_PATH` so nodes are immediately runnable

First build takes 3-5 minutes. Subsequent builds are cached and fast.

## Step 4 — Test with Discovery Server (3 Terminals)

Open **3 separate PowerShell windows** (Windows) or terminal tabs (Linux/Mac).

### Terminal 1 — Start the container and the Discovery Server

```bash
docker run -it --name ros2_test ros2_discovery_test bash
```

Inside the container:
```bash
fastdds discovery -i 0 -p 11811
```

Expected output:
```
### Server is running ###
  Participant Type:   SERVER
  Server ID:          0
  Server GUID prefix: 44.53.00.5f.45.50.52.4f.53.49.4d.41
  Server Addresses:   UDPv4:[0.0.0.0]:11811
```

Leave this terminal running.

---

### Terminal 2 — Run the Talker (Publisher)

```bash
docker exec -it ros2_test bash
```

Inside the container:
```bash
export ROS_DISCOVERY_SERVER=127.0.0.1:11811
ros2 run generated_pkg talker
```

Expected output:
```
[INFO] [talker]: Publishing: 'Hello from talker! count=0'
[INFO] [talker]: Publishing: 'Hello from talker! count=1'
[INFO] [talker]: Publishing: 'Hello from talker! count=2'
```

---

### Terminal 3 — Run the Listener (Subscriber)

```bash
docker exec -it ros2_test bash
```

Inside the container:
```bash
export ROS_DISCOVERY_SERVER=127.0.0.1:11811
ros2 run generated_pkg listener
```

Expected output:
```
[INFO] [listener]: Received: Hello from talker! count=0
[INFO] [listener]: Received: Hello from talker! count=1
[INFO] [listener]: Received: Hello from talker! count=2
```

## Step 5 — Verify Discovery Server Is Actually Being Used

### Test 1 — Kill the server, watch communication stop
Press `Ctrl+C` in Terminal 1. The listener in Terminal 3 stops receiving messages within a few seconds.
Normal DDS multicast pub/sub would survive this. This proves your nodes depend on the discovery server.

### Test 2 — Check node visibility without the env var
Open a 4th terminal into the container:
```bash
docker exec -it ros2_test bash
```

Without the discovery server env var:
```bash
ros2 node list
# Returns nothing — nodes are invisible to normal discovery
```

With the env var:
```bash
export ROS_DISCOVERY_SERVER=127.0.0.1:11811
ros2 node list
# Returns: /talker  /listener
```

### Test 3 — Echo the topic
```bash
export ROS_DISCOVERY_SERVER=127.0.0.1:11811
ros2 topic echo /chatter
```

## Starting a New Project

1. Create a new project folder:
```bash
cp -r discovery_server_single_pub_sub/ my_new_project/
```

2. Edit the YAML files in `my_new_project/config/` to define your new system.

3. Run the generator targeting the new project:
```bash
python tool/generator.py --project my_new_project
```

4. Rebuild the Docker image and test.

The `tool/` folder never changes. Only the project folder changes.

## Fast-DDS Discovery Server Reference

The `tool/` folder contains two XML profiles:

| File | Purpose |
|---|---|
| `client.xml` | Configures ROS2 nodes as `SUPER_CLIENT` — connects to the server instead of using multicast |
| `server.xml` | Optional — configures a participant as `SERVER`. Usually not needed since `fastdds discovery` CLI handles this |

To use `client.xml` instead of the `ROS_DISCOVERY_SERVER` env var:
```bash
export FASTRTPS_DEFAULT_PROFILES_FILE=/path/to/tool/client.xml
```

Server GUID prefix for server ID 0: `44.53.00.5f.45.50.52.4f.53.49.4d.41`
For server ID N, change byte 3: `44.53.NN.5f.45.50.52.4f.53.49.4d.41`

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| `Package 'generated_pkg' not found` | `AMENT_PREFIX_PATH` not set | The Dockerfile sets it via `ENV` — rebuild with `--no-cache` |
| `fastdds: command not found` | ROS2 not sourced | Run `source /opt/ros/jazzy/setup.bash` first |
| Listener receives nothing | Discovery server not running or env var missing | Ensure Terminal 1 server is up; check `ROS_DISCOVERY_SERVER` is set in both Terminal 2 and 3 |
| Docker build uses stale cache | Old layer cached | Run `docker build --no-cache -f tool/Dockerfile -t ros2_discovery_test .` |
| `"/generated_pkg" not found: not found` | `docker build` run from wrong directory | Must run from `discoveryTesting/` not from inside `tool/`. Use `-f tool/Dockerfile` with `.` as context |
| `"/entrypoint.sh" not found: not found` | Same wrong build directory | Same fix — run `docker build -f tool/Dockerfile .` from `discoveryTesting/` |
